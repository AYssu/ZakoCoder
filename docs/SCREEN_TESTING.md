# 当前设备屏幕操作

“Android 屏幕识别与操作”是全局可选能力包，默认关闭。它观察和操作当前手机屏幕，不要求工作区、Android 工程或 Debug APK。开启能力包、取得系统权限和授权本次任务是三个独立步骤。本文描述实现契约，实际验证以验收记录为准。

## 使用流程

1. 从侧边栏「能力包」开启屏幕能力，进入「配置屏幕操作」。没有工作区也可管理。
2. 选择无障碍或 Root 操作方式。无障碍由用户在系统设置开启；Root 只在点击申请时请求。返回应用会刷新真实连接状态。切换方式撤销当前任务授权。
3. 在手机上打开希望操作的页面，并向助手说明目标。首次设备操作必须明确批准本次任务，不能由能力开关、普通工具规则或 YOLO 代替。
4. 授权面向当前设备，可在不同应用之间操作；不是只允许某个 APK。系统安装与授权页面仍由用户处理，不自动同意系统权限。
5. 助手优先读取界面节点，再执行点击、输入、滑动和返回；操作前重新检查前台与有效快照。具体失败保留在对话和本地记录中，命令受理不代表验证成功。
6. 可随时从配置面板或悬浮卡停止。任务结束、取消、关闭能力包、切换操作方式或进程重启后，撤销任务授权及截图分享；下一任务重新确认。

构建、项目测试和 APK 安装继续使用原有开发流程。安装来源权限和系统安装确认仅用于安装，不再作为屏幕操作前提；选择或安装一个 APK 也不会授予设备控制权限。

## 任务授权与隐私

任务授权仅绑定当前任务及本次租约，不跨任务保存，不在进程恢复时自动重建。被拒绝时不会开始屏幕读取或操作。禁止规则仍优先；关闭能力包不加载对应工具定义和专属说明，也会撤销正在使用的租约。

授权范围覆盖当前设备，可能接触其他应用的可见内容；用户应在开始前关闭私密页面。密码节点与敏感窗口不采集。Android 系统安装、权限授予等确认由用户处理；Root 和无障碍均不代替这些决定。

「发送屏幕截图给模型」默认关闭，只有活动任务获授权后才可单独开启。确认中明确说明设备画面可能包含其他应用内容，并会发送到所配置的模型服务。工具不能自行修改该开关；停止或任务结束后清除。未分享截图时仍可使用节点与文字结果，不能声称看过图像。

## 操作方式与系统边界

| 方式 | 能力 | 用户授权 |
| --- | --- | --- |
| 无障碍 | 读取节点、点击、输入、滑动、返回与支持设备上的截图 | 系统无障碍开关及本次任务授权 |
| Root | 使用设备 Root 读取和操作界面 | 显式 Root 申请及本次任务授权 |

Android 8–10 可读取节点，截图需要 Android 11 或以上。Root 截图仍需无障碍服务用于画面安全检查；不使用无法排除覆盖窗口的任意全屏截图。Android 14 起可使用窗口截图；Android 11–13 在截图前后检查覆盖窗口并裁剪区域，不能保证排除两次检查间短暂出现又消失的窗口。

Root 文本输入限已聚焦输入框的可打印 ASCII；中文和替换整段文本使用无障碍输入。不读取或覆盖系统剪贴板。节点输出限制数量、大小和有效期，跨应用或快照失效需重新观察。

## 动作回执与等待条件

点击、长按、输入、滑动、节点滚动和返回只派发一次。随后在有界时间内重新读取节点，结果包含：

| 字段 | 含义 |
| --- | --- |
| `dispatched` | 动作已经提交给系统；不保证页面或业务完成。 |
| `observed_change` | 观察范围中的节点投影发生变化为 `true`、完整投影相同为 `false`，无法比较为 `null`；不是像素差异或完整应用状态。 |
| `verified` | 指定等待或断言条件已核实；单纯点击或画面变化保持 `false`。 |
| `unknown_reason` | 观察不可用、缺少基线、部分投影或没有指定后置条件等固定原因。 |

成功读取的最新节点作为 `observation` 返回，含新的快照令牌；后续动作必须引用新快照中的节点。页面没有变化时可以有限重读节点，不自动补发原点击或输入。超时、取消或后置读取失败不能证明副作用没有发生，应重新观察再决定下一步。

- `wait_until`：提供非空、最多 1,000 字符的 `text`，可指定 1–20,000 毫秒的整数 `timeout_ms`，默认 5,000 毫秒。只观察当前非敏感节点，等待文字或描述包含该内容；命中返回已核验，超时返回 `verified=false` 与 `condition_timeout`，不执行额外点击。等待不是模型轮询，不处理密码节点。
- `scroll`：提供 `snapshot`、当前可滚动 `node` 和 `direction`。方向为手指的 `up`／`down`／`left`／`right`，在目标节点内操作；节点失效或不可滚动明确失败，不能退回任意屏幕坐标盲滑。
- `assert_text`：保留原有文字断言行为，与实际动作受理分开判断；成功只证明当时的文字条件，不证明颜色、布局或完整业务正确。

这些回执不会持久保存完整节点、截图或用户输入正文。浏览器 DOM 操作属于另一独立能力，设备节点断言也不等于网页 DOM 验证。

## 后台、悬浮卡与记录

活动屏幕任务申请开发前台服务；通知和电池优化可从「设置 → 权限管理」集中管理。进行屏幕动作或其他真实开发操作时使用有界 CPU 唤醒锁，空闲时释放。不能保证阻止厂商清理、强制停止或系统终止；被终止后不自动重放输入、点击、安装或命令。

悬浮入口默认关闭，需要用户授予系统悬浮窗权限并开启。活动授权期间显示横向卡片，直接展示正在执行的动作；展开查看本轮公开对话、详情、返回助手和停止操作。浮窗不展示内部思考、原始工具结果或凭据。执行屏幕操作时先暂时隐藏，等待真实画面同步后执行；完成后恢复原状态，取消或失效租约不会恢复旧窗口。

动作有总超时与独立后端命令上限；超时说明实际阶段，不统一归因于后台被结束。输入或点击不会因超时自动重放，应先重新观察。记录保持有界并通过控制器在 IO 调度器读取，界面不直接操作进程、磁盘或网络。

## 原生界面规格

面向希望助手操作手机的用户，关键词为明确、克制、可停止。沿用 Kotlin + Compose、Miuix 主题和既有字体，不引入网页或额外配色。

顺序为：能力包 → 当前设备与任务授权状态 → 操作方式 → 对应真实系统权限 → 截图分享 → 悬浮卡 → 操作记录／报告 → 可展开边界说明。不显示 APK 选择器、构建前提或工作区空态。停止操作置于活动任务卡，至少 48dp 触区。其他按钮使用次级样式，所有错误有具体文字。

卡片内距 16dp、组内间隔 8／12dp、圆角 12dp，文字复用应用字阶。所有主题颜色取 MaterialTheme；日夜模式均须截图核对。长包名及错误自然换行，面板可滚动且尊重底部安全区。

## 验证范围

- 纯 UI：无工作区可管理、无 APK 入口、真实权限状态投影、任务授权等待／活动／停止、截图确认及错误文案。
- 后端：任务 lease 隔离、拒绝、跨应用快照切换、敏感窗口、停止后拒绝旧调用；动作仅派发一次、观察失败回执、可滚动节点与等待条件的成功／超时／取消。
- 实机：使用独立测试应用验证节点与输入，不读取用户个人应用内容；固定状态截图不得冒充真实权限和操作链已通过。

实际设备结果与日夜截图由本次交付记录给出，本文不将测试计划标记为已通过。既有项目 APK 安装链路可独立验证，不再证明设备屏幕授权。
