# Android 应用屏幕测试

“Android 屏幕识别与操作”是独立的可选能力包，按项目启用且默认关闭；不与 SSH 包或构建工具捆绑。本模块把同一项目的构建产物、系统安装和界面验证接到助手工具流程中。构建和项目测试继续使用终端／项目命令；屏幕测试只操作用户选择的调试 APK。该文档描述实现契约，验证状态以本次提交的实际测试记录为准，不把测试计划视为已经通过。

## 开发与测试流程

1. 在项目库选择 Android 工程，配置构建和测试命令；让助手编辑、执行项目测试并构建 Debug APK。
2. 打开「设置 → 开发能力 → 能力包」，或从助手右上角更多菜单进入“能力包”，为当前项目开启“Android 屏幕识别与操作”，再点击“配置屏幕操作”。面板绑定当前项目，不接收任意包名。APK 列表来自当前项目的实际构建产物，显示包名和相对路径，非调试包无法授权。当前仅接收独立 APK，不接受需要其他代码／资源分包的 split 安装；单个 APK 的摘要不能证明其他分包也是当前构建。未构建时明确引导先构建再刷新。
3. 若尚未授予安装来源权限，点击 APK 目标区域的「允许安装应用」，进入当前宿主包专属的系统安装来源设置。用户自行开启后返回，面板自动刷新为紧凑的已允许提示；这不等于确认安装，实际安装仍需系统确认。随后选择测试方式，再选择并授权 APK。包内测试方式初始选择为普通，支持安装和启动；能力包自身仍默认关闭，不要求开启无障碍或 root。切换测试方式会停止当前测试并清空 APK 授权，必须重新选择。
4. 无障碍方式需用户打开系统无障碍设置并开启 ZakoCoder；返回后面板自动检查连接。Root 方式仅在用户点击「申请 root 授权」后检查并申请 Root 权限。未取得权限时仅提示检查设备的 Root 权限设置并重试，不根据请求结果推断设备授权界面的行为。
5. 在助手中描述要验证的流程和预期结果。安装需用户在系统界面确认。只有安装后的包名、调试标记、签名及 APK 内容摘要符合所选制品，才允许界面操作；同版本号的旧安装包也会拒绝。助手依次查看界面、执行交互、检查结果；需要修复时回到源码，重新构建并授权新的 APK，避免用旧安装包冒充新版本验证。
6. 面板显示实际状态与失败原因；有活动测试时提供「停止本次测试」。测试报告读取控制器的有界内容，不在 Compose 中访问磁盘；报告可选择复制。停止或结束测试不代表测试通过，报告保留实际结果。

## 发现构建产物与超时诊断

`android_test status` 返回当前项目中实际发现的最多 10 个有效调试 APK 候选路径、包名及截断标记。助手可以调用 `android_test prepare` 提出候选路径，审批展示控制器实际解析的包名、路径和 SHA-256；即使工具规则为允许或已授予任务内权限，该步骤仍需明确确认。发现不等于选择或授权；预览制品只校验内容、身份及摘要，不建立测试租约。用户批准后会重新校验 APK 字节摘要，审批期间制品变化会拒绝选择，要求重新确认。

屏幕动作包含 APK 内容校验、前台窗口检查及后端操作，总预算为 60 秒；结束动作仍为 20 秒。Root 子命令保持独立的 8／12 秒上限。错误区分制品校验、画面同步及后端命令阶段，不将所有超时归因于后台被结束。悬浮窗隐藏后最多等待 5 秒完成画面帧同步，未完成则不执行屏幕操作。任何输入、安装与启动动作均不会因超时自动重放，应先重新观察，确认实际状态后继续。

## 后台执行与权限入口

「设置 → 权限管理」集中查看通知、文件、安装来源、悬浮窗、无障碍、Root 和电池优化状态，并进入对应系统设置。系统权限、模型工具规则及测试目标授权分别生效；打开管理页面不会自动授予权限。

活动屏幕测试即使未开启悬浮窗，也会申请开发前台服务；服务状态可在权限页核对。AI、构建、项目命令或屏幕动作正在执行时使用带超时并续期的 CPU 唤醒锁，结束或停止后释放；仅有空闲终端或测试入口时不持有该锁。前台服务使用持续通知，用户可停止全部任务。电池优化设置由用户决定，不宣称能够阻止厂商清理、强行停止或系统终止。服务被结束时取消所属任务，不自动重放点击、安装或命令。

## 按需观察与上下文

能力包关闭时不向模型发送 `android_test` 定义及屏幕专属说明。开启后优先读取结构化界面节点：无障碍方式直接读取目标节点树，Root 方式使用受限 `uiautomator dump`。节点输出有大小、数量及有效期限制，并附当前快照令牌；交互前重新校验目标、节点及前台窗口，旧快照失效时应重新观察。读取节点不要求模型具备图片理解能力。

截图供颜色、排版、图像等节点不能表达的检查使用，由模型按需调用，仍需要用户单独开启分享且模型支持图片输入。截图只证明捕获瞬间的画面，不能替代交互结果或真实断言。关闭能力包会停止相关操作并撤销目标及临时截图分享；以后重新开启仍需重新选择目标，不恢复旧任务授权。构建及安装的外部副作用不会因此回滚。

屏幕包与 SSH 远程开发包共享管理入口，但互不代替。SSH 的认证、远程命令、SFTP 与 tmux 不要求开启手机屏幕权限；远程工具的工作目录、取消与并发修改限制见[产品范围](PRODUCT.md#可选能力包)。管理界面规范见[能力包设计](CAPABILITY_PACKAGES_DESIGN.md)。

## 三种测试方式

| 方式 | 能力 | 用户授权 |
| --- | --- | --- |
| 普通 | 系统安装确认、启动已选择的构建产物；构建与项目测试使用独立工具 | 选择项目的调试 APK，系统安装确认 |
| 无障碍 | 界面节点、点击、文本输入、滚动及支持设备上的截图 | 选择 APK，系统无障碍授权 |
| Root | 结构化设备交互与结果检查 | 选择 APK，显式申请 root 授权 |

Android 8–10 可读取界面节点，截图需 Android 11（API 30）或更高版本。Root 方式的截图同样需要启用无障碍服务；不会使用无法隔离悬浮窗的全屏 root 截屏。Android 14 起使用目标窗口截图，Android 11–13 检查截图前后的覆盖窗口后裁剪目标区域；系统截图接口无法严格排除两次检查之间短暂出现又消失的覆盖窗口，这些版本不提供与 Android 14 目标窗口截图相同的隔离保证。Root 文本输入限已聚焦输入框的可打印 ASCII，中文及替换文本使用无障碍输入，不读取或覆盖系统剪贴板。密码节点与敏感窗口不采集。Root 不作为绕过目标应用范围、签名或敏感画面检查的理由。Android 系统安装页、授权页仍由用户决定，助手不得自动同意权限或安装。

「发送测试截图给模型」默认关闭，仅在无障碍／Root 方式显示，选择 APK 后方可开启。开启前需单独确认画面将发送到配置的模型服务，并确认当前模型支持图片输入。AI 不能自行更改此选项；停止或结束测试后重置。模型不支持图片时仍可使用界面节点与文字报告，不能假称已经看过截图。

## 分层授权与可选悬浮入口

AI 工具规则中的“允许（Allow）”只省略该工具的模型调用审批，不代表授予 Android 权限、选择测试 APK、允许安装或允许截图分享。一次／任务内授权也不绕过能力包开关、当前项目、所选制品、任务会话租约、前台与遮挡检查；“禁止”始终优先。系统安装与权限页面由用户处理，Root 或无障碍方式不能代替这些确认。

屏幕测试悬浮入口默认关闭。用户可在屏幕操作面板显式进入当前应用的系统悬浮窗授权设置，再开启入口；只有已授权且存在活动测试时才显示。入口默认收起，仅在用户展开后显示当前目标、测试状态和有界的本轮公开对话摘要，可收起或拖动，并提供返回助手和停止任务。摘要只接收当前项目及当前目标租约的公开消息，不包含内部思考、原始工具结果；停止或切换目标会清空。入口不提供安装、授权或模型执行的快捷绕过。执行界面操作前隐藏悬浮入口，避免本应用窗口遮挡目标；操作结束后按当前状态恢复。关闭入口不撤销已有系统权限，也不代表正在运行的任务已停止，停止应使用明确的停止操作。悬浮窗授权、Root 授权、工具审批和截图分享互不替代。

本轮验证计划及尚待完成的实际结果见[缓存与屏幕入口审查记录](reviews/2026-10-31-cache-screen/README.md)，不得把设计契约或固定状态截图当成真实权限链路已通过。

## UI 设计规格

**用户与场景**：在手机上开发 Android 工程的用户，需要知道当前测的是哪个项目、哪个 APK、用了哪种权限，以及实际测到了什么。设计关键词为清晰、克制、可停止；沿用原生 Kotlin + Compose 与现有应用主题，不引入网页页面。

**结构顺序**：设置开发能力行／助手更多菜单 → 能力包 → 为当前项目开启屏幕包 → 配置屏幕操作 → 项目名称 → 测试方式 → APK 目标 → 对应授权状态 → 截图分享 → 实际测试记录／停止／报告 → 可展开的能力说明。当前方式只呈现自身授权入口，普通方式不展示无障碍状态。APK 选择与报告使用独立底部 Sheet，避免把长列表塞进输入框或设置主页。Root 方式的可展开说明明确标注截图仍需无障碍、文本输入限可打印 ASCII，并提供直接打开系统无障碍设置的文字按钮；不为这些说明新增审批弹窗。

**尺寸与文字**：以 360dp 为基准，Sheet 沿用现有 18dp 水平内距；组内 16dp，间距 8／12／16dp，圆角 12dp。标题和正文沿用 WorkbenchTypography（弹层标题 19sp、卡片 16sp、正文 13sp、辅助 12sp）。所有可操作行和按钮触区至少 48dp。包名使用等宽字体，相对路径和失败原因允许换行；面板及报告整体可纵向滚动，小屏和字体放大时不把操作挤出布局。

**色彩**：工具效率行业的蓝色占小面积，仅强调主操作和状态；亮色背景 `#F5F7FA`、表面 `#FFFFFF`、正文 `#0F172A`、次文 `#5B6B82`、主色 `#2563EB`。暗色沿用 `#0B0F14`、`#151B23`、`#E6EDF3`、`#9BA7B4`、`#4C8DFF`。错误使用主题 errorContainer/onErrorContainer，并同时显示具体文字原因，不单靠颜色表达。无额外渐变、插画或远程资源。

**完整状态**：未选项目；安装来源尚未允许／返回后已允许；APK 查找中；无可用产物；真实 APK 列表；授权前／已连接／授权失败；运行中；停止；有报告；报告读取中／失败。异步错误保留面板、已选项目与选择上下文；取消协程保持取消语义，不转成虚假的操作失败。

实际执行结果和日夜截图见 [验收记录](SCREEN_TESTING_VALIDATION.md)。

## 验证与截图要求

`ScreenTestUiDeviceTest` 使用仅在测试进程生成的状态与报告 fixture，覆盖日间和夜间的未选项目、安装来源未允许／已允许及授权入口回调、普通／无障碍／Root、APK 空列表与选择、已选目标、活动测试、具体失败和报告正文；同时验证回调和 360dp／放大字体布局。Fixture 不写入生产控制器，不构造生产假日志，也不申请无障碍或 root。

这些 UI 测试只证明显示和交互契约。真实安装、目标范围、节点输入、截图、停止及日志还需要控制器／后端真机测试，不能用静态截图代替。实际截图由统一的真机测试负责人归档到提交对应目录，附设备、主题、测试来源和运行结果；未执行时应明确标为未验证。

## 自动化验证入口

- `ScreenTestControllerDeviceTest`：目标范围、调试包选择、停止与审计。
- `ScreenTestAccessibilityDeviceTest`：真实目标节点、中文输入、点击与断言、截图、密码保护、过期授权，以及同版本重建后项目／安装制品不一致的拒绝与系统安装入口。
- `AiScreenTestDeviceTest`：审批与禁止项、任务授权隔离、临时截图请求、历史持久化和取消。
- `AiAndroidWorkflowDeviceTest`：本地 HTTPS 模型协议 fixture 驱动真实已安装应用，观察后选择实际节点，点击、重新观察、断言、发送真实截图像素、结束并撤销授权。它不验证商业模型的决策能力，也不宣称在该用例内执行过构建或安装。
- `RootScreenTestSafetyTest`：固定参数转义、超时、节点标识及 OEM 窗口格式和遮挡校验。`ScreenTestRootDeviceTest` 需单独为测试宿主授予真实 Root 才能运行；编译及单元测试不能代替真机通道验收。

真实测试目标源码位于 `test-fixtures/screen-app/`，仅供显式设备验收，不是生产预置项目或构建依赖。UI 测试状态与真实屏幕闭环的报告分开归档，不能混称为应用功能测试全部通过。现有 `AndroidBuildDeviceTest` 单独验证 Ubuntu 内 Java／Kotlin 构建及安装 URI 交付，运行前需已安装托管工具链。

本轮权限、后台服务、APK 目标提议及悬浮窗的实际验证范围与日夜截图见[用量与权限验收](USAGE_AND_PERMISSIONS_VALIDATION.md)。
