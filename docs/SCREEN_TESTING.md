# 虚拟屏幕操作

「虚拟屏幕」是全局可选能力，默认关闭。当前生产入口只在 Root 模式、Android 11 / API 30 及以上创建专用虚拟显示，不操作手机主屏，不绑定工作区 APK，也不要求开启无障碍服务。权限选择见[设备权限与 Shell](DEVICE_ACCESS.md)。

本文说明当前实现契约，不能替代具体设备上的验收记录。

## 开始调试

1. 在「设置 → 权限配置」明确启用 Root 模式，并完成授权。系统已有 Root 不代表应用已获许可。
2. 从「能力包 → 设备调试」开启虚拟屏幕，打开详情。未满足权限时可直接进入权限配置。
3. 可启动虚拟屏幕，选择本机已安装且可启动的调试应用，刷新查看本地画面；也可以让助手按包名启动应用。此入口不负责安装 APK。
4. 让助手说明目标，按当前 Ask、Auto、Yolo、Only 规则批准本次任务。能力开关、设备模式和任务授权分别管理。
5. 助手先读取虚拟显示中的节点，再执行点击、输入、滑动和断言。无法确认应用位于指定显示时明确失败，不回退到主屏。
6. 可关闭虚拟屏幕或停止任务。任务结束、取消、超时、关闭能力、Root 撤销、切回基础模式或显示更换后，旧租约失效并释放显示。

Ubuntu 构建、系统 APK 安装、SSH 和网页调试沿用各自流程，不因虚拟屏幕能力改变执行身份。单例 Activity 或厂商系统可能拒绝副屏启动；启动请求已受理不代表应用已在虚拟显示就绪。

## 范围与隐私

授权仅覆盖本次任务及对应虚拟显示，绑定当前 Root 权限代次，不跨任务保存，也不在进程恢复时重建。禁止规则仍优先。关闭能力不加载对应工具定义和专属说明，并停止正在使用的屏幕任务。

虚拟屏幕隔开的是显示空间，应用安装、账号和数据仍与手机共享，不能当作独立沙箱。宿主、权限控制器、系统授权等敏感界面不能作为普通调试目标。密码节点不公开；安全窗口禁止截图，无法确认窗口安全时拒绝捕获。

「向模型分享截图」默认关闭，只能在活动任务获授权后由用户开启。确认后，本次任务的虚拟画面可发送至配置的模型服务；停止或任务结束自动关闭。未分享截图时仍可使用允许的节点和文字结果，助手不能声称看过图像。详情页的本地预览不会自动开启模型截图分享。

## 动作回执

点击、长按、输入、滑动、滚动和返回只派发一次，随后在有界时间内重新观察节点：

| 字段 | 含义 |
| --- | --- |
| `dispatched` | 动作已经提交，不保证页面或业务完成。 |
| `observed_change` | 节点投影是否变化；无法比较时为 `null`，不代表像素或完整应用状态。 |
| `verified` | 指定等待或断言条件是否核实；单纯点击或画面变化不能直接标记通过。 |
| `unknown_reason` | 缺少基线、观察不可用、部分投影或未指定后置条件等原因。 |

后续动作引用最新观察的快照与节点。快照过期、显示更换或 Root 被撤销均失败，不自动接管其他窗口。超时或取消不能证明副作用没有发生，应重新观察后决定下一步；不会自动重复点击和输入。

- `wait_until`：等待非敏感节点出现指定文字；文本非空且最多 1,000 字符，整数 `timeout_ms` 范围为 1–20,000，默认 5,000 毫秒。超时返回未核实，不执行额外点击。
- `scroll`：使用当前快照内的可滚动节点，指定 `up`、`down`、`left` 或 `right`，不能回退为主屏坐标滑动。
- `assert_text`：成功只证明当时的节点文字条件，不代表颜色、布局或完整业务正确。

操作状态包含虚拟显示 ID。记录有界保存任务、动作、结果和退出原因，不把节点全文、输入正文或截图像素写入普通审计日志。浏览器 DOM 验证仍属于独立网页能力。

## 界面与后台

能力页按设备调试、网页调试、远程开发分类。权限配置提供基础 / Root 模式，虚拟屏幕详情只保留实际状态、启动、应用选择、画面刷新、停止与当前任务截图分享，不再提供普通 / 无障碍 / Root 后端选择。

设置和初始化复用同一权限组件，详情返回保留实际父页。布局沿用 Kotlin + Compose 和 Miuix 主题，使用真实主题色及系统安全区；日夜模式和关键授权状态均需设备截图验证。

通知和电池限制从「设置 → 权限配置」管理。系统仍可结束进程，Root 不保证永久后台运行；重启后不自动重放操作。关闭或失效租约需要释放专用显示及 Root 服务连接，不能用隐藏主屏操作替代失败的虚拟显示。

## 验证与历史

每次发布分别验证权限拒绝 / 撤销、应用启动归属、观察与输入、截图限制、停止清理、旧租约拒绝及日夜界面。只编译通过或固定状态截图不代表真实设备操作已通过；设备范围和未验证项以交付记录为准。

历史版本曾使用当前物理屏幕的无障碍 / Root 后端，并曾有工作区 Debug APK 选择链路。这些是历史契约，旧记录与旧测试只证明对应版本的行为，不代表当前生产入口仍提供物理屏幕控制。项目 APK 安装仍可独立使用，但安装成功不授予虚拟屏幕任务权限。
