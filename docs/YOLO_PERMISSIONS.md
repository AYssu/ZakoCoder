# 项目工具权限

助手盾牌入口提供普通、高权限和 **YOLO · 全自动** 三种项目预设，默认仍是普通。权限按项目保存，重启后保留。

| 模式 | 应用内工具审批 |
| --- | --- |
| 普通 | 安全读取自动允许；修改、执行、终端读取、MCP、屏幕和 SSH 等按当前规则询问。 |
| 高权限 | 项目工具自动允许；MCP、屏幕、SSH 默认询问；保留已有禁止项，可从高级规则单独调整。 |
| YOLO | 明确确认后替换全部已有规则，自动允许所有助手工具，包括已启用的 MCP、屏幕与 SSH。 |

YOLO 会自动允许文件修改、命令与远程副作用，不提供安全隔离。界面先展示作用范围及持久化说明；选择该行不会立刻授权，确认后才保存。取消不改变原规则。此模式仅改变工具审批，不扩大项目文件工具的路径范围、不覆盖冲突保护，也不将终端变成宿主 Shell。

## 能力和系统授权仍分别管理

- 屏幕、SSH 能力包仍需按项目主动开启，YOLO 不会开启它们，也不会向未启用的包加载工具。
- 屏幕操作限当前项目可验证的有效 Debug APK。YOLO 可自动选择该项目的 APK；普通和高权限仍需要确认具体产物。已选择的目标租约发生变化时，旧任务不得跟随新目标。
- 无障碍、root、安装确认及其他 Android 系统授权仍由用户或系统管理；YOLO 不会代授予，也不会绕过系统拒绝。
- SSH 连接信息及首次主机指纹信任仍由用户管理，YOLO 不绕过主机指纹变化拒绝。
- 截图分享仍由用户单独控制，YOLO 不自动把图片发送给模型。
- 外部网络、依赖安装、远程文件和进程等副作用不能由本地检查点完整回滚。

## 运行中调整

切换策略只在成功保存后生效，并撤销本任务的临时工具及目标授权。正在等待的工具审批会按新策略重新判断：切入 YOLO 可继续原调用，切回普通后后续调用重新询问。文件规则刷新期间撤销 YOLO 时，在真正执行副作用前也会重新检查授权。已经运行的操作不会因更换预设自动终止，需要停止任务。

修改高级规则会离开 YOLO，按显示的默认及逐工具规则执行。普通和高权限的预设切换继续保留已有禁止项；进入 YOLO 的确认说明会明确告知其替换禁止项。

## 数据兼容

项目策略新增 `yolo` 布尔值，缺失时为 `false`。旧版已有的“默认允许”自定义配置不会被当作 YOLO，也不会因此获得跳过 APK 目标确认的能力。YOLO 不是模型文本或 Skill 能开启的工具参数。

## 定向验证入口

- JVM：`AiPermissionPresetsTest`、`AiScreenTestPolicyTest`、`AiPermissionsTest`。
- Android：`AiYoloPermissionDeviceTest` 验证控制器真实授权入口、等待中切换、能力包和目标边界、项目持久化兼容；执行器使用隔离测试替身，不操作真实远端或授予系统权限。
- 原生 UI：`AiYoloPermissionUiDeviceTest` 验证确认、取消及撤销，导出日夜各三张实际页面截图至测试包 `files/screen-review/product-polish/`。

实现与测试源码的存在不代表已经通过；实际构建、测试及截图结果以本次 PR 验收记录为准。
