# 设备权限与 Shell

「设置 → 权限配置」和首次初始化提供基础模式、Root 模式。这里选择的是设备能力的执行身份，AI 工具的 Ask、Auto、Yolo、Only 审批模式保持独立。

## 两种模式

| 能力 | 基础模式（默认） | Root 模式 |
| --- | --- | --- |
| Ubuntu 开发与项目终端 | 原有 PRoot 环境 | 原有 PRoot 环境 |
| 设备 Shell | Android 应用身份 | 已获授权的系统 Root 身份 |
| 虚拟屏幕调试 | 不可用 | Android 11 / API 30 及以上按需启动 |
| SSH、网页调试 | 按原有能力与授权使用 | 按原有能力与授权使用 |
| AI 工具审批 | 保持当前审批模式 | 保持当前审批模式 |

普通应用启动 `/system/bin/sh`，子进程仍使用应用 UID；这不等于 ADB 的 Shell UID，也不等于 Ubuntu 内的用户身份。普通模式的系统文件、日志和应用管理操作可能被 Android 拒绝，不能据此认为命令工具失效。

Root 模式需要手机已经具备可用 Root，并由用户明确确认。未取得授权时显示失败，不回退成“假 Root”，也不会自动开启 Yolo。保存 Root 模式偏好不意味着授权永远有效，每次连接与关键操作仍需检查实际身份；升级不会把历史屏幕 Root 授权自动转换为全局 Root 模式。

## 系统权限

开启 Root 模式时，应用会尝试配置本应用可用的通知、文件访问、安装来源和电池限制权限。不同系统不一定允许全部操作，界面以重新查询的真实状态为准；未成功的项目仍可从权限配置跳转系统设置。

这不意味着接管其他应用的权限或自动同意任意系统确认，也不保证厂商不会结束后台进程。Root 管理工具自身的弹窗、拒绝和隐藏策略由系统及该工具管理。

切回基础模式会撤销本应用持有的 Root 使用资格、停止设备 Shell，并关闭虚拟显示。不会擅自回收用户之前在 Android 设置中授予的通知或文件等权限，也不会改变 Root 管理工具中的永久授权设置。

## AI 如何选择执行位置

项目构建、安装开发依赖、运行服务继续使用 Ubuntu 工具。只有需要访问当前手机宿主环境时才使用独立设备 Shell 工具。执行过程区分 Ubuntu 与 Android，记录真实身份、命令输出、退出码和超时状态；设备 Shell 不会暗中切换到 Ubuntu 或 SSH。

设备 Shell 是可选全局能力。工具调用仍接受当前 AI 审批模式管理；开启能力或取得 Root 并不等于批准未来所有命令。运行命令可能修改系统及应用数据，操作前应核对范围。任务取消不会自动撤销已经产生的文件、网络或系统副作用。

SSH 连接沿用自己的远端身份、主机信任和凭据；网页访问沿用原有网页能力。两者不因设备模式切换获得或失去手机 Root 权限。

## 虚拟屏幕

虚拟屏幕是 Android 11 / API 30 及以上的 Root 设备调试能力。应用为任务创建专用显示，在其中启动目标应用、读取节点、点击、输入和按需截图；不把操作回退到手机主屏，也不需要开启原来的无障碍服务。

虚拟显示不是独立容器或另一台手机：它与本机应用共用安装包、账号和数据。单例 Activity、应用自己的启动约束及厂商策略可能拒绝独立显示；无法确认应用在目标显示运行时会报错，不将主屏启动算作成功。系统权限界面、宿主授权页面及敏感节点受保护，安全窗口禁止截图。

任务授权绑定当前权限代次和虚拟显示，不能在另一个任务或新的显示中复用。停止、任务结束、取消、操作超时、切回基础模式或关闭虚拟屏幕会撤销租约并释放显示。进程被终止后不自动重放点击、输入或命令。

画面预览仅在本机显示；向模型发送截图需要另行开启当前任务的截图分享，默认关闭。详见[虚拟屏幕操作](SCREEN_TESTING.md)。实际设备支持与验证结果以对应版本交付记录为准。
