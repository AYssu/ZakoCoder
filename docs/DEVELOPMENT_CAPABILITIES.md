# 开发能力决策与验收边界

本文记录本地项目、工具权限及开发辅助能力的设计决策，供实现和审查使用。它不是已实现功能清单，也不替代产品范围或发布说明。评估基线为 2026-10-30 的 `67647fb` 源码（后续实现以产品文档为准）；后续实现须用代码、测试与设备记录更新状态，不能仅据本文宣布完成。

## 目标与优先级

产品目标是让用户在手机上围绕同一份真实源码完成编辑、运行、验证和恢复。每增加一种执行能力，都必须保留项目归属、用户授权、可取消性和实际结果。

| 能力 | 决策 | 优先级与交付条件 |
| --- | --- | --- |
| 原位绑定本地目录 | 应做。项目副本与原位绑定分别展示，编辑器和运行环境必须使用同一份源码。 | P0；完成存储身份、执行挂载、解除绑定安全与重启验证。 |
| 模型参数、思考呈现、上下文和请求头 | 应围绕实际模型能力做，不能用统一开关承诺所有服务兼容。 | P0；传输、历史、日志脱敏、配置迁移共同验收。 |
| 普通／高权限预设 | 应做简化入口，复用现有工具 Allow / Ask / Deny 策略。 | P1；高权限仅表示应用内审批预设，不表示 Android root。 |
| 开发包管理 | 保留并完善现有工具包、异步检测、安装日志与项目依赖入口。 | P1；优先处理失败定位，不另建完整 apt 图形前端。 |
| 本地网页预览与健康检查 | 已有终端和预览入口，值得贯通开发任务；保留就绪检查与真实地址。 | P1；HTTP 可访问不等于页面正确、可交互或测试通过。 |
| SSH 客户端 | 有实际远程开发需求时做；首步可提供可选 openssh-client 工具包。 | P2；连接管理与凭据 UI 是独立功能，不能只加一个按钮声称远程开发完成。 |
| 只读编码子代理 | 技术可行，价值在定位与独立审查；建议作为后续受控实现，不默认并发编辑。 | P2；任务隔离、授权继承、预算、取消和恢复满足前不接入生产工具。 |
| 浏览器自动测试 | 有价值，但须与 ARM64 实际浏览器运行环境验证；优先用户浏览器预览和项目测试。 | P2；验证具体浏览器制品与驱动版本，不默认 Playwright 下载即可在 Android PRoot 运行。 |
| 打开用户选定应用 | 可用 Android Intent 实现，适合安装后手动验收入口。 | P2；由用户操作触发、指定目标，不承诺后台随时拉起应用。 |
| 跨应用点击、截图、自动操作 | 不作为当前编码主链路前置条件。需单独明确的调试模式与用户需求。 | P3；不能通过普通权限预设获得无障碍、ADB 或 root 能力。 |
| SSH 服务端、通用包商店、全设备自动代理 | 暂不建议加入当前产品。 | 需要长期网络服务、授权、更新和设备控制维护，当前收益不足以抵消复杂度。 |

P0 是正确性和数据一致性的前置条件；P1 是现有能力的可用性完善；P2/P3 是实现顺序建议，不是承诺日期，也不表示已交付。

## 本地目录：必须贯通整个项目身份

### 当前证据与改造位置

当前 `ProjectRepository.import()` 经 DocumentsContract 将树复制到私有 `workspaces/<UUID>`。`directory()` 只返回并校验此根；这解释了为什么用户在应用修改后，原磁盘目录不变。项目标识只保存 id、name、kinds，未保存来源类型和外部根。

文件操作已有集中根解析接缝：`EditorFileStore`、`AiProjectFiles`、`AiSkills`、检查点和项目命令配置接收 `(String) -> File`。应由单一项目根解析器提供身份，避免每个模块分别解释来源。需要同时检查以下执行链：

- `Workbench` 创建 `ProjectRepository(context, runtime.workspaces)`，向编辑器、AI 与项目任务传入目录解析。
- `LinuxRuntime.command()` 当前将整个私有 workspaces 绑定为 `/workspace`，以 `/workspace/<UUID>` 为 cwd；`execute()` 再直接验证 `File(workspaces, projectId)`。只改文件仓库会造成“编辑的是外部、构建的是内部”的分裂。
- 终端、有限命令、MCP stdio 与 Git 均须从同一解析结果建立 guest 绑定。项目名称用于显示，UUID 用于稳定挂载；含空格或中文的实际路径始终是 argv 数据，不拼进宿主 Shell。
- `Workbench` 项目移除与失败清理当前包含 `PrivateFiles.deleteTree(projects.directory(id))`。绑定项目必须只移除登记；绝不能沿这条路径递归删除用户源码。创建失败回收也只能清理应用自己创建的临时根。
- 项目库的容量、安装 APK、依赖检测、项目规则发现、变更导航与草稿恢复，都需要按来源解析，不能仍写死私有根。

### 两种来源不能混淆

1. **可访问的真实目录**：用户显式选择或输入真实文件系统目录，应用通过实际访问与平台授权校验后记录 canonical 根。编辑、文件工具和 PRoot 绑定共享该根，不建立隐藏副本，也不自动后台双向同步。非系统可读写目录显示真实错误，不尝试猜路径、提权或回退到旧副本。
2. **文档提供者目录**：`content://` 是授权的文档标识，不保证存在稳定 POSIX 路径，远程提供者更可能按需下载内容。必须使用 ContentResolver / DocumentsContract，保留持久 URI 权限并处理撤销。当前大量开发工具只接受 POSIX 目录；不能把 SAF 的直接编辑支持描述成原位终端构建。可继续显式导入副本，或另做文档提供者编辑后端，清楚标记执行限制。

Android all-files access 也是单独的系统授权。即使获准，也不等于其他应用私有目录、全部 Android/data 或云文档可用。选择 SAF 授权不自动授予真实路径权限；应用内“高权限”也不能替代系统权限。需要申请 `MANAGE_EXTERNAL_STORAGE` 时，必须在用户主动绑定遇到权限缺失后说明用途并进入系统设置，回来重新检测，拒绝后保持现有项目可用。Google Play 对此权限有分发政策限制，须在决定分发渠道时另行核实。

### 身份、外部变更与删除

项目来源需要版本化持久化，旧登记迁移为原私有工作区，不能重建或移动现有文件。外部目录丢失或权限被撤销时仍保留项目登记，标记不可访问并允许重新绑定；不能静默从列表剔除。更换根时检查项目是否有运行任务、打开草稿与恢复操作，避免把旧内容保存到新目录。

应用自身的会话、审计、草稿和检查点保留在私有存储，不强制污染源码。项目自定义 Skill／规则等用户主动创建的项目内容需说明目标路径。直接绑定的源码会受到用户、其他应用及终端并发修改；保存与恢复必须比较当前基线并呈现冲突，不能用最近一次内容覆盖外部更新。检查点不等于全目录事务，终端命令、依赖安装与网络操作仍可能不可逆。

绑定根及文件操作必须拒绝链接逃逸、越界路径和失效授权；canonical 校验不代表抵御所有恶意并发链接替换。共享外部目录不能宣称强安全沙箱。PRoot 的“root”只是 guest 身份模拟，PRoot 本身不是隔离同 Android UID 进程的安全边界；批准 Shell 意味着允许在应用 UID 可访问的环境执行代码，而非只能修改指定文件。

验收要求：

- 在手机真实共享目录建立含中文、空格名称工程；编辑器保存、AI 文件修改、终端写入和项目构建看到同一内容，由应用外读取再次确认。
- 强制结束并重启后仍指向同一原目录；旧私有项目正常加载，目录失效保留登记并明确提示。
- 解除绑定不删除任何源码；失败回滚、删除操作、导出和清理缓存均不递归清理外部根。
- 外部编辑与脏缓冲、检查点恢复冲突时拒绝无提示覆盖；链接逃逸、重复目录绑定、只读目录、授权拒绝／撤销有可复现结果。
- `content://` 文档树不经字符串推断为路径；仅提供副本时页面明确说“导入副本”。
- PRoot 的终端、有限命令与 MCP stdio 均实际验证 cwd 与读写目标，不只测试文件列表。

## 工具权限：两个入口，保留逐工具细则

当前 `AiExecution.kt` 已有 `AiPolicy`、Allow / Ask / Deny、写操作标识，以及 Once / TaskTarget / TaskTool 审批。`AiPermissionStore` 保存用户规则。无需另建一套平行权限系统。

建议界面预设：

- **普通**：允许项目定位和读取；写文件、命令、终端输入、关闭、MCP 及可能含敏感内容的终端／日志读取保持审批。当前默认策略已接近此行为，应保留兼容。
- **高权限**：明确列出将免审批的工具范围、项目范围与有效期；建议仅本次任务生效。拒绝规则仍优先，MCP 外部副作用默认继续审批。用户若希望永久保存，应额外显式选择，不因切换按钮覆盖已有细则。
- **自定义**：保留现有逐工具高级设置，以免已有 Deny 被预设悄悄改成 Allow。用户取消高权限后清理任务临时授予，不更改真实系统授权。

高权限名称旁需要直接解释“减少工具审批，不获得 Android root”。不能把 Shell 进行含义分类后称作安全白名单；Python、sed、包安装脚本和任意命令均可产生非文件副作用。跨工具绕过拒绝、Skill 宣称授权、MCP 提示要求提权均应被系统规则和实际 gate 阻止。审批 UI 和日志记录项目、工具、目标、授权来源、开始／结束／退出码，绝不保存凭据原文。

验收：普通与高权限的真实工具调用、现有 Deny 优先、切换项目与重启、任务结束与取消后的授予失效、加载配置失败默认收紧。MCP 与子代理不能通过另一个传输绕过主任务拒绝。

## 编码子代理：可行，先做只读角色

当前 AI 控制器围绕单个会话、全局 active、共享当前项目、单轮工具队列与权限待决状态工作，不具备可直接复制多个控制器就安全并行的隔离保证。对 Operit 的源码参考只表明其具有 `run_ui_subagent` 和 PhoneAgent 这类 UI 自动操作链路，不能据名称推断已有可复用的并行编码事务。

手机执行子代理实际是并发调用用户模型服务，不要求本地加载多个大模型，但会增加网络请求、Token 成本、电量与上下文占用。对当前用户最直接的价值是“独立找文件”和“独立列出审查清单”。建议首版仅只读定位／审查，每次由主任务显式派发，默认最多一个子任务；不同时提供多个可写 worker、无界递归或自动花费扩张。

可接入条件：

1. 每个子任务有独立 id、父任务 id、只读快照上下文、所用模型／计费来源、状态、取消 Job、日志和可恢复结果；主会话压缩不能丢失未完成任务。
2. 子工具集合与权限最多是父任务的交集，禁用 Shell、终端输入、写入、外部 MCP 和创建新代理。只读也会向模型发送源码，需在派发前遵守父任务的数据范围。
3. 总并发数、单任务与总体输出预算、超时、停止条件是可见的资源控制；不是隐藏的模型请求次数上限。取消父任务须取消网络／等待，并将已知完成与未知远程状态分别记录。
4. 结果为带文件位置、证据和不确定性的建议，不自动应用补丁，不改变权限，不作为测试通过证据。文件变化时附读取时版本，让主任务重新核实。
5. 设备终止后不擅自重启可能计费的调用；保留中断状态，用户决定继续。配置更新与密钥不能跨子任务通过文本复制。

在这些条件完成前，保留单代理工作流是准确的实现边界。后续若要并发写入，应先有独立工作区／分支、明确文件所有权、补丁合并和冲突 UI，不能通过锁住一个写函数就宣布并行编码安全。收益验证应比较相同任务的定位正确率、审查有效问题数、耗时与实际 Token 成本，而非只看能创建代理。

## 工具包、SSH 与远程开发

开发工具包已经由 `DevelopmentTools` 维护探测命令、包名与安装脚本，环境页显示可选列表；项目依赖另有检测。最值得完善的是安装前后版本、失败退出码、镜像／DNS／代理错误区分，以及“安装了包但当前项目缺少依赖”的清晰状态。包安装脚本属于实际代码执行，取消后需重新检测真实状态，不显示假回滚。

SSH 首步建议仅可选 `openssh-client`，通过用户终端连接。正式连接管理须增加独立主机档案、端口与用户名、首次主机指纹确认、变更指纹阻止、私钥导入及 passphrase 生命周期；不能使用 `StrictHostKeyChecking=no` 默认绕过认证。凭据私有保存、日志脱敏，不发送给 AI，不把私钥写进项目或命令预览。远程工作目录、命令取消与断线后的未知结果须明示；本地检查点无法恢复远程修改。

SSH 服务端不自动启用，不默认为局域网开放端口，更不和 AI 的“高权限”绑定。需要服务端能力时独立评估认证、监听地址、前台生命周期、通知与关闭入口。当前没有连接管理实现时，文档不能声称完整远程开发支持。

验收覆盖实际 ARM64 客户端、正确／变更主机密钥、认证失败、断线、取消、密钥不进入请求／日志／导出、重启后不自动执行连接。无需为一个工具包新增通用第三方扩展市场。

## 预览、调试与安装后打开

当前真实终端可以启动 Python HTTP、Vite 等服务，终端预览页能提取并手填地址。应将“打开网页”保持为用户明确点击动作；开发服务默认回环地址，只有用户需要跨设备访问时说明局域网绑定和端口。服务状态区分进程运行、HTTP 探测成功、页面加载和实际交互验证，不把四者混为“预览成功”。

可以先做的窄功能是让项目运行页显示既有终端、服务 URL、上次 HTTP 检测结果、日志跳转和停止入口，复用终端控制器，不再创建第二套隐藏后台服务。HTTP 探测要有限超时、不携带模型凭据，重定向重新验证地址，不能作为探测任意内网的无授权入口。

打开浏览器／应用与自动调试是不同能力。Intent 能打开系统匹配的处理程序，失败要给出没有处理程序等明确反馈。打开用户刚安装的 APK 可走指定包名的系统启动入口，Android 包可见性与后台启动限制仍有效；不申请全应用枚举来替代有目标的声明。不从模型文本直接构造任意 Intent URI 或宿主 Shell `am` 命令。

网页交互自动化可选择远端用户授权的浏览器服务，或验证确实兼容本机 ARM64 Ubuntu PRoot 的浏览器与驱动；桌面 Linux ARM64 支持不等于 Android 内核／PRoot 运行已通过。内嵌 WebView 能提供应用自己的调试通道，但改变网页宿主、安全、存储和 JavaScript 边界，不应为了截图临时添加不受限 JS bridge。WebView 调试只在显式调试场景启用，不能默认开放生产调试端口。

Android UI 自动化需要区分：

- 项目的应用测试：优先构建可安装 APK、运行项目自身单元测试／仪器测试，保留报告。Instrumentation/UI Automator 是测试执行工具，并不赋予普通生产 APK 控制全部应用的能力。
- 手机宿主控制：无障碍、ADB／无线调试、root 等是另一种系统授权与攻击面。连接状态、目标包、截图隐私、逐任务同意、随时停止必须独立设计；当前不引入常驻全屏读取和点击。

前台服务只能帮助表达持续任务，不能承诺不被系统或厂商结束。现有 DevelopmentService 使用 `specialUse`，不能把 Android 15 的 dataSync／mediaProcessing 六小时限制直接套到它；仍须按应用 target SDK、实际服务类型和分发要求验证。后台自动拉起界面还受 Android 的独立限制。

验收应包含真实服务启动→就绪探测→手机浏览器访问→终端停止→地址失效完整链路，以及后台／锁屏／系统结束后的真实状态。只有实际执行过页面断言或测试报告，才可列为 UI 测试通过；人工打开页面只能写人工预览。

## 独立用户体验审查建议

以下为基于当前入口和状态模型的独立建议，尚不代表已完成的设备可用性研究。先处理阻止完成任务的状态，再改视觉细节。

| 优先级 | 问题与用户影响 | 建议与验收 |
| --- | --- | --- |
| P0 | 导入、绑定、工作副本名称混用，用户以为已修改原文件。 | 项目卡与详情展示来源、真实位置／提供者、只读或不可用原因；首次添加立即确认编辑对象，移除操作写清“不删除源码”。 |
| P0 | 运行失败只显示终端尾部，无法判断下载、包、项目或模型问题。 | 错误页保留阶段、可展开原日志与脱敏复制；建议动作绑定实际失败证据，不默认重装所有环境。 |
| P1 | 项目、模型、权限、会话属于不同范围，离开页面易失去当前执行身份。 | 会话顶部保持项目名和运行状态，输入区保留模型和权限入口；切换项目前处理活动任务和草稿，清楚显示旧任务归属。 |
| P1 | 单次授权、整轮授权、高权限可能难区分。 | 审批就近显示目标与有效期，默认最小授予；拒绝后展示结果，不能把关闭弹层当批准。 |
| P1 | 设置项堆在聊天页挤占正文与输入。 | 模型、上下文与扩展高级配置使用现有 Sheet／独立设置页；聊天只留高频切换和当前状态。保持48dp触摸区，不能为了紧凑缩小到不可点。 |
| P1 | 服务运行与 AI 轮次结束混淆，用户不知道是否应该继续等。 | 分别显示 AI 状态与项目终端状态；完成摘要列修改文件、实际验证、未验证项，持久服务有单独停止按钮。 |
| P2 | 多文件草稿、编辑预览与返回路径难追踪。 | 保存状态、外部冲突、引用文件定位高亮及返回行为统一，预览不丢光标和脏缓冲。 |
| P2 | 小屏图标和长路径挤压布局。 | 依据 mobile-ui-design-kit 检查360dp、中文长名称、字体1.3倍、键盘打开和深色模式；重要信息换行，操作使用已有菜单或Sheet。 |

独立验收脚本应让新用户从空环境添加真实项目，配置自己的模型，完成一次代码修改并在手机看见页面或安装结果，再处理一次人为制造的构建错误和一次外部文件冲突。记录卡住的位置、误解的范围与重复操作，不以开发者熟悉界面作为通过标准。
