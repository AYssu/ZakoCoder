本次在隔离工作树 `test/android-compatibility` 上验证，基于 `ca07083` 加本轮未提交变更。没有推送、发布或修改日常真机配置。APK 摘要、系统 fingerprint、实际安装 ABI、页大小和逐项日志保存在本地 `build/compatibility/summary.json` 及其引用的报告目录；这些生成文件被 Git 忽略。

- 应用检查包括真实编辑器输入、实际 IME、Markdown 预览、草稿与保存冲突、模型配置、本地 TLS 对话及流式输出、亮暗和 1.3 倍字体、触控范围。
- SAF 使用系统目录选择器授予真实目录 URI；验证授权前拒绝读取、导入副本独立、释放持久授权及 Provider 主动撤销全部授权后拒绝读取。
- 三个恢复阶段分别是准备、外部 force-stop 后新进程恢复、较高 versionCode 覆盖安装后恢复并清理。实际校验应用 UID、不同 PID 和版本递增，以及项目、草稿、模型／设置、会话和文件检查点保留。
- Ubuntu 选择固定摘要的 x86_64 镜像；验证真实 Shell／PTY、Unicode 与带空格路径、退出码、取消和子进程回收。Python HTTP 服务在 Activity 停止／恢复后仍可访问，关闭所属终端后端口关闭。
- 通知用例在 API 33 及以上明确授予 POST_NOTIFICATIONS 后运行，不能据此推断用户拒绝通知时也有相同显示效果。

## 发现及复测

| 现象 | 定位与处理 | 设备证据 |
| --- | --- | --- |
| Android 11 目录选择器不显示测试根目录 | 旧系统 DocumentsUI 缺包查询权限；仅测试 APK 使用 `--force-queryable`。没有给产品或 fixture 授予文档读取权限 | API 30 SAF 授权前／撤销后拒绝访问、系统授权后导入均通过 |
| 流式截图偶发捕获到已完成任务 | 用例依赖固定 20 秒等待；改成本地真实 SSE 响应结束屏障和心跳，截图时确认任务及网络响应仍活跃 | API 31 定向日夜复测和后续系统矩阵通过 |
| Android 12L 真实触摸注入失败 | 增加窗口／焦点证据，完整手势有限重试；仍要求真实 IME 可见 | `api32-focused-final` |
| Android 14 输入连接 commit 返回失败 | 等待原生编辑器绑定、聚焦和可编辑状态，使用一次新连接提交，保留内容断言 | `api34-focused-final` |
| Android 15 预览标题未及时检测到 | 等待同一缓冲区实际更新，从当前 Activity 的 Compose 语义树验证真实预览；保留撤销、选区与磁盘断言 | `api35-runtime-final/preview-focused.log` |

上述同步调整位于仪器测试，未将失败改为跳过。运行器严格拒绝空测试组、崩溃、失败和跳过结果，并将安装目标限定为隔离测试包族。

## 最低支持版本的额外探针

另在官方 Android 8.0／API 26 x86_64 镜像（内核 `3.18.91+`）验证了 20 项本地应用用例，启动、文件导入、编辑器、实际键盘、入口布局、模型配置保存、目录浏览、能力包和预览通过。

该设备不能记为完整兼容：

- Ubuntu／Python 安装触发 PRoot `tracee/event.c:718` 的 `IS_IN_SYSENTER` 断言，后续终端、HTTP 和通知验证未执行。原始结果位于 `api26-local-final`。这是旧版 x86_64 系统上的真实运行环境失败；没有据此推断 ARM64 Android 8 一定失败，也没有修改最低 SDK 或静默绕过错误。
- 模型网络测试因 MockWebServer 5.5.1 服务端读取 SNI 时 `getRequestedServerNames` 返回 null 而崩溃。HTTP/1 与 HTTP/2 使用相同的请求记录路径，未做无效协议降级。生产客户端是否受影响尚无证据，API 26 模型网络对话明确未验证，原始失败保留在 `api26-minimum`。
- 额外探针修复了入口用例直接读取 API 30 `stateDescription` 的问题，改为 `AccessibilityNodeInfoCompat`，原展开／收起断言仍严格执行并通过。

这些结果不改变上面的 Android 11–17 基线，但发布说明不能据此宣称 Android 8 的完整开发运行环境已通过验收。

## 构建与边界

默认 ARM64 Debug 构建、Lint、425 项 Kotlin/JVM 单元测试、14 项原生构建校验测试、仓库结构检查及手动工作流 actionlint 已通过。默认 APK 实际只包含 ARM64；实验 x86_64 为显式构建参数。

- 这些是 AOSP x86_64 模拟器结果，不能替代各厂商真机的后台、电池与权限策略验证。
- 所有矩阵设备实际页大小为 4096。原生库执行了 16KiB ELF 对齐静态检查，但没有在真实 16KiB 页设备运行。
- 覆盖升级比较本次代码的 versionCode 1 → 2，不代表所有历史数据 schema 迁移。
- 模型网络使用本地 TLS fixture，不调用收费服务，不代表商业模型质量验收。
- 本轮不适配 x86_64 Android SDK／NDK。早期额外的 Node/npm 全工具安装探针在 npm 安装后检查失败；不计入本轮通过项，也不宣称完整 x86_64 工具链可用。
- [手动兼容性工作流](../.github/workflows/android-compatibility.yml) 已完成本地语法检查，尚未推送或在 GitHub 执行。CI 使用 Google APIs 镜像，不能把本地 AOSP 镜像结果当作其远端运行结果。

日常小改动只跑受影响的检查；首次基线、发布前或 target SDK、权限、存储、原生运行时和进程生命周期等大变更后再跑全版本矩阵。操作入口见 [兼容性验证说明](ANDROID_COMPATIBILITY.md)。
