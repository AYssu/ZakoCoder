# Agent 分工、执行额度与验证

对话页「更多 → 任务与自动分工」提供按会话保存的开关，默认关闭。开启后，模型可按需使用 `delegate_readonly` 分派 `scout`（查找）和 `reviewer`（审查），每批 1–2 项、最多两个并行。简单任务仍直接执行；开启开关只增加工具描述，不强制增加模型请求。

助手使用当前配置的模型、协议和参数，各自持有独立的消息上下文。只向父任务返回最多约一万字符的结论或部分证据；主代理不自动收到助手的文件写入基线，修改前仍需亲自读取。助手的模型请求在现有「请求诊断」标注助手身份，实际文件读取也有独立工具事件，汇入现有用量统计。

## 权限和生命周期

子代理执行器硬编码允许 `list_files`、`read_file`、`search_files`。只提供当前策略为 Allow 的工具；Ask 不视为授权，不让并行助手争抢单个审批界面。执行读取时重新检查权限。写文件、命令、终端、MCP、SSH、屏幕测试、递归分工和自动加载 Skill 均不在允许列表。YOLO 也不能扩大这个列表。路径与敏感文件规则复用主代理的原生文件工具。

父任务保持唯一写入者，主代理工具批次继续串行执行。子代理依附父任务协程，Stop 会取消所有请求并等待清理。一个助手失败不会抹掉已完成兄弟任务的结果；返回值明确区分完成、包含读取异常、达到额度和失败。中止后不自动重跑子任务或恢复后台代理。

## 每次任务的执行额度

`AiTaskSession` 统一管理主代理、子代理、摘要和传输重试：最多 80 次请求尝试、240 次工具、45 分钟和约 200 万累计输入/输出 Token。累计 Token 包含重复发送的上下文，是消耗保护值，不是上下文窗口；服务未返回完整用量时使用明确标注的本地估计，不推算金额。询问用户后续接保留已有计数；主动「继续任务（补充额度）」开始新任务额度。

每次真实传输尝试之前执行请求准入，因此重试不能绕过请求额度；已进行中的请求有剩余任务时间约束。文件操作或命令开始前和后续安全边界检查额度，已执行的工具必须先与结果配对，才暂停下一步。已经启动的命令沿用它自己的超时与清理规则，不为了任务额度强行截断副作用；因此总耗时不是精确到毫秒的硬停止保证。审批等待也计入运行时间，等待后执行前再次检查。

相同工具和实际参数连续失败/被拒三次会暂停。比较忽略顶层 `reason`、调用 ID 和 JSON 对象键序；成功工具会重置连续失败次数。并非任意三次错误都会停止。暂停时给未执行的同批调用补取消结果，在现有历史容量允许时保存完整配对上下文，并添加本地产生的暂停说明。若历史本身已超过持久化上限，仍保留原有有界恢复说明与检查点，不承诺无限保存工具输出。重载后点击继续，模型能看到已完成和被延后的操作；检查点、审批与既有恢复说明继续有效。

## 长上下文

`AiContextSummarizer` 独立负责摘要请求策略，控制器保留网络、审批、用量和持久化所有权。原始摘要输入能装入窗口时仍只发一次摘要请求；超长时按实际序列化后的 Token 估计寻找最大可容纳片段，滚动保留目标、已完成操作、验证、失败与未完成事项。每个原始字符都会进入某一片段，不用截掉中间内容来假装摘要成功。

摘要是有损记忆，不是权限或正确性证明。固定需求、规则、Skill 或图片本身仍过大时保留原有明确失败；不会无限压缩。摘要、纠正请求和分段请求都消耗相同任务额度，耗尽时可保存原上下文并继续。

## 模型配置默认值

新建配置默认「按服务预设配置」。用户明确选择协议或服务预设时自动恢复自动兼容配置，并清理该协议不支持的旧参数。例如 Responses 清除 seed/惩罚项，Anthropic 开启思考时清除采样项并保证显式输出上限大于思考预算，Gemini 不保留 Max 档位。默认优先沿用服务自身行为；未知中转服务使用协议通用默认值，不猜测模型能力。

仅打开旧配置不会修改已有手动设置。切换模型保留当前协议/兼容选择并沿用已有的上下文窗口推荐逻辑。服务地址切换不会绕过密钥/请求头来源检查。「可连接」「工具调用可用」「思考设置未验证」仍分别报告。

## 自动验证与真机复现

```sh
ANDROID_HOME=/path/to/android-sdk python3 scripts/test_agent_optimizations.py --serial DEVICE_SERIAL --build
```

脚本构建同时包含 ARM64/x86_64 的 Debug APK、运行 JVM 测试和 Lint，再升级安装应用和测试 APK，执行本地 TLS 模型夹具及 UI 测试。不会卸载应用、安装 Ubuntu、调用付费服务或使用个人模型配置。签名不匹配时直接失败，禁止为了测试删除用户数据。

证据默认保存在忽略目录 `build/agent-validation/<UTC>/`：源码状态及变更文件摘要、APK SHA-256、设备架构/API、各步骤退出码、完整 instrumentation 输出及限定标签的设备日志。失败或超时也保留诊断材料；可将 `report.json` 与失败测试名称关联到同一构建。UI 截图位于应用缓存 `ui-review/agent-settings/` 和现有协议/兼容选项截图目录。

自动覆盖包括独立上下文、并行调度、恶意写入/命令/递归调用拦截、权限禁止、真实文件读取、兄弟任务部分失败、Stop 传播、助手轮数限制、主/子共享请求额度、重试额度、整批结果配对、历史重载继续、重复失败、分段完整性、摘要纠正、Skill/规则/动态证据保留，以及协议切换和小屏大字体 UI。

## 对比方法和已知边界

受控夹具验证两项独立任务的并行调度是否重叠、开启但未调用助手是否仍只请求一次，以及原先超出摘要请求窗口的任务能否继续。这些结果说明执行路径，没有证明真实模型一定更快或更会写代码。并行助手会增加请求与 Token；串行依赖任务、服务并发限制和移动网络都可能使它更慢。

真机接入后，使用同一项目快照、模型、协议、参数、网络，分别关闭/开启分工，各至少运行三次，记录成功率、真实验证结果、请求次数、Token（缺失项单列）、总耗时和修改范围。建议固定十项任务：单文件定位、跨文件调用链、独立两模块查找、已有修改审查、小错误修复、跨文件修复、构建失败定位、重复工具失败、长输出续接、Stop 后继续。所有写入/命令仍按现有权限审批；速度取中位数，失败不能从统计中删掉。

2026-11-06 已在 USB 接入的 23049RAD8C / ARM64 / Android 13（API 33）真机上运行相同验收集，71/71 通过；包含子代理、四种协议、额度续接、取消、长上下文和小屏大字体昼夜 UI。应用与测试 APK SHA-256 均与通过模拟器验收的版本相同，升级安装保留原应用数据。原始结果、限定标签日志、源码摘要及截图保存在忽略目录 `build/agent-validation/usb-arm64-run/`。

真实服务的并发/思考兼容、真实项目成功率及端到端延迟尚未验证。真机本地夹具通过不代替这些结论。相关优化仍在同一个分支，尚未创建 PR。
