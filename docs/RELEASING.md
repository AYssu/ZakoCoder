# 发布流程

当前没有正式发行或自动发布工作流。CI 只构建与检查，不公开分发验证 APK，不签发正式版本，也不上传应用商店。现有 PRoot／loader 验证制品仍存在发行来源与许可门槛，Release 任务被阻止；仅修改版本或关闭构建检查不能解除该限制。

## 解除发行门槛

1. 固定可追溯的 PRoot 源码、补丁、构建工具链和产物摘要，完成可复现自编译并替换验证制品。
2. 补齐对应源码、许可证、声明及分发义务；以[第三方说明](../THIRD_PARTY.md)为准，不移除上游声明。
3. 对替换后的制品重新验证安装、归档保护、取消、PTY、派生进程、工作目录与生命周期。
4. 维护者审查上述证据及实际平台范围后，才调整 Release 构建门槛。

运行环境细节见[运行环境](RUNTIME.md)。

## 版本与数据

采用 SemVer 风格 `MAJOR.MINOR.PATCH`；每次公开 Android 包的 `versionCode` 严格递增。开发版使用 `-dev`，预发布使用 `-alpha.N`／`-beta.N`。应用与环境包独立版本，不假设应用升级会替换已装环境。

0.x 版本也应说明配置与数据兼容性。持久格式或协议破坏性变更需迁移说明、旧数据读取与失败恢复验证；不能通过强制降级或清数据解决升级问题。

## 发布检查

- 在干净 checkout 执行仓库检查、构建、Lint 与相关测试，确认无需本地参考材料；命令见[开发规范](DEVELOPMENT.md)。
- 验证升级安装保留项目、模型配置、会话、草稿和记录，检查启动不自动重放任务及副作用。
- 审查应用权限、依赖、原生制品来源、许可证、签名及 SHA-256，确认测试 CA、测试入口、凭据和临时数据不进入正式包。
- 根据实际覆盖说明 Android、架构、目录提供者、终端及工具链范围，明确未覆盖的最低版本、新系统和厂商差异。
- 维护者确认 applicationId、名称、版本与 changelog；不将开发目标或模型计划写成已交付功能。
- 在仓库外安全保管签名密钥和口令，避免进入源码、普通 CI 环境及日志；校验最终签名与制品摘要。
- 发布说明包含安装与升级方式、已知限制、数据丢失边界、资源来源、摘要与许可证。

维护者批准后才创建版本 tag、推送及 GitHub Release。当前没有自动完成这些操作的发布脚本；任何本地检查通过都不等于发布授权。

## 仓库管理

管理员配置默认分支、主分支保护、与现有工作流对应的必需检查、审查要求、禁止强推和私密漏洞报告。CODEOWNERS 只列实际可用的维护者，不预置虚假责任人。安全响应入口应在首次公开发行前核实可用。

## 事故处理

出现数据损坏、泄密或恶意制品时停止发行，保留脱敏证据并撤下受影响制品。说明影响版本、临时措施、恢复方式和后续修复；不得直接强制回滚用户数据。泄漏密钥需要撤销与轮换，删除提交不能代替处置。修复增加针对性回归，再按同一门槛重新发行。
