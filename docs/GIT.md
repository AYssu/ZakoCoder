# 项目 Git 工作流

Git 页面与项目终端复用 Ubuntu 中的 Git 和同一项目目录。没有额外仓库副本；在界面进行拉取、合并、暂存和提交都会修改该目录。先安装 Ubuntu 和 Git 工具包。

## 同步仓库

- **获取**更新远端跟踪信息，不合并工作目录。
- **拉取**先获取，再尝试快进；出现分叉时停止，由用户选择明确的分支合并。
- **推送**发送当前提交到确认的远端分支，不提供强制推送。
- 领先／落后数量来自本地已获取的上游记录，不代表服务器的实时状态。确认操作前核对远端和目标分支。

操作期间显示实际进程输出，可取消。取消网络连接并不等于撤销已经完成的远端推送或本地修改；应重新确认仓库状态。

## 私有 HTTPS 仓库

克隆时开启私有仓库选项，填写服务要求的用户名及访问令牌。已有仓库可在 Git 页为所选 HTTPS 远端管理凭据。令牌需具备对应仓库的读取／推送权限，应用不会替用户扩展服务端权限。

凭据按项目、HTTPS 来源及仓库路径绑定，使用 Android Keystore 加密，排除系统备份，不回填令牌；删除项目时删除其凭据。不把令牌写入远端 URL、项目文件、命令参数、Git 配置或 AI 会话。单次执行通过私有命名管道向 ASKPASS 传递令牌，不把明文令牌存成普通文件；完成／取消后清理临时脚本与管道，启动时清理旧版遗留。禁止跨来源重定向，保持 TLS 校验。联网前若检测到仓库 `insteadOf` / `pushInsteadOf` URL 重写规则，会停止并说明原因，用户核对后自行处理；应用不会自动删除规则。

PRoot 与普通终端共享应用 UID，不能作为凭据隔离边界。获准执行任意 Shell 的进程可能读取同 UID 下的短时管道或进程内容；不要在不受信任的并发命令运行时使用仓库凭据。

已有 `ssh://` 远端使用 Ubuntu 的 SSH 身份和严格主机指纹校验。HTTPS 表单不配置 SSH；尚无 Git 专用 SSH 密钥管理界面。不会跳过未知主机校验。

## 分支与冲突

可以新建、切换和明确合并分支。Git 自身检查未提交修改，不自动 stash，不清理或强制重置工作目录。合并提交使用本次填写的作者身份，不更改全局 Git 身份。

冲突文件单独列出：打开编辑器处理内容并保存后，再确认标记解决。标记解决只执行暂存，不判断业务合并是否正确；核对内容并运行验证后再提交。中止合并由用户确认，Git 若因后续修改拒绝中止，会保留错误输出。

编辑器未保存缓冲区与 Git 磁盘修改可能不同；编辑器会提示磁盘变化，保存仍受原有摘要保护。不要在确认前丢弃草稿。

## 范围

不提供 rebase、强推、仓库托管账号登录、Git LFS 管理或子模块递归推送。远端新增／编辑仍使用终端。网络失败会保留分类提示及有界输出；输出并非完整服务器审计日志。
