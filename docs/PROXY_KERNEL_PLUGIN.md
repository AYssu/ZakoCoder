# 代理内核插件

ZakoCoder 使用独立、可选的 Xray 内核插件。主 APK 不包含 Xray 二进制，也不要求 Go 工具链；直连和手动 HTTP／SOCKS5 代理不需要插件。需要内核节点时，用户另行安装与主应用同证书签名的插件 APK。

## 支持范围

| 类型 | 当前范围 |
| --- | --- |
| HTTP／SOCKS5 | 直接连接，不依赖插件；SOCKS5 支持账号密码。 |
| VMess | 内核转发；具体传输和安全参数须通过应用校验。 |
| Shadowsocks／Trojan | 内核转发；未知加密方式或传输参数不会静默忽略。 |
| VLESS | TCP／RAW、WebSocket、gRPC；TLS 可用于这三种传输，REALITY 仅用于 TCP／RAW 与 gRPC（WebSocket + REALITY 不受内核支持）；`xtls-rprx-vision` 仅用于 TCP／RAW。明文仅限本地／私网字面地址；参数不完整或其他尚未适配组合显示不支持。 |

协议可解析、配置可生成、内核启动成功和远端实际连通是不同状态。应用不把订阅中的本机回环说明条目算作可用远端节点；“可用”表示当前支持该节点配置，不保证远端服务在线或当前网络可达。

VLESS 的支持范围限定在本表所列组合，不表示已覆盖 Xray 的全部协议、传输或订阅格式。真实订阅的连通结果受远端服务与网络影响，不能以本地配置校验或测试服务代替。

## 安装与恢复

在代理设置的内核插件区域，选择在线下载或从本地 APK 安装。应用先校验包名、签名、接口兼容与版本，再交给 Android 系统安装器确认；不提供静默安装。

出现“内核插件服务不可用”时：

1. 确认主应用与插件来自兼容版本和相同签名渠道。
2. 点击插件区域的打开入口，或从桌面手动打开 **ZakoCoder 内核插件**，再返回主应用重试。插件页面仅用于显式打开应用，不读取订阅，不启动代理。
3. 若旧版插件没有打开页面，入口会转到系统应用详情，可先更新插件。安装后仍不可用时，检查系统是否允许主应用关联启动插件；设置项名称由手机系统决定。
4. 打开内核诊断，复制或导出文本，附上操作步骤提交 Issue。

显式打开插件可以处理首次安装后的停止状态，但不能保证解除厂商系统的关联启动限制；不需要清除主应用数据。OnePlus／Android 16 曾反馈系统拦截主应用启动插件，日志含 `OplusAppStartupManager: prevent start`。本轮增加恢复与诊断入口，尚不能据此认定该设备已恢复，需受影响设备重新验证。

## 诊断与隐私

诊断包含 Android SDK、主应用与可信插件版本号、插件启用／停止状态、Binder 连接状态、最近最多 24 条固定事件代码与时间。绑定失败区分拒绝、安全异常、超时、空绑定、连接死亡、连接断开和远端调用失败。

诊断不读取或导出订阅链接、节点地址、节点名、端口、UUID、密码、自定义配置、设备唯一标识或原始异常文本。事件保存在进程内存，重启后不保留；需要反馈时应在复现后及时复制或导出。应用无法读取其他进程或厂商系统完整日志，仍可能需要 ADB 日志进一步定位。

## 进程与权限边界

- 插件包名为 `dev.zakocoder.app.kernel`；服务使用显式组件绑定，受 `dev.zakocoder.app.permission.KERNEL` 签名级权限保护，AIDL 方法再次校验调用权限。
- 主应用按自身实际签名证书校验插件，而非信任插件自报证书。不同签名来源的 APK 不能随意混用。
- 公开的激活 Activity 不提供内核控制、文件操作或配置接收接口，不放宽服务权限。
- 主应用生成配置并通过 Binder 传入。插件在自己的私有缓存写配置，从自身 `nativeLibraryDir` 执行随 APK 安装的 Xray。不会从可写目录下载并直接执行内核。
- 本地 SOCKS5 入站仅监听 `127.0.0.1`，每次启动生成随机认证凭据；停止时删除配置并结束内核进程。
- 内核启动就绪检测执行真实 SOCKS5 认证；它只能证明本地入口就绪，不代表远端节点连通。
- 插件进程死亡时主应用清理失效连接；系统仍可能回收应用或阻止跨应用启动，不保证后台持续运行。

## 节点域名与故障诊断

主应用在 IO 调度器通过 Android 系统解析节点域名，对去重后的地址在单次整体预算内逐个执行有界 TCP 可达性探测，优先 IPv4，但 IPv6 和其他解析地址均作为回退；每次探测前检查停止／切换代际和协程状态，取消异常继续向上传播；成功后把实际地址传给内核连接，TLS／REALITY 的服务名和 WebSocket Host 保留原配置。这样不依赖静态 Go 内核读取 Linux 的 `/etc/resolv.conf`。启动或切换节点时重新解析；所有地址均不可达时明确显示连接失败。

诊断 v2 分别报告插件绑定、内核进程是否存活、退出码和最近一次启动日志的固定错误类别。日志只读取末尾 64 KiB，不返回原始日志、节点地址或凭据；`none_observed` 只表示未匹配错误类别，不表示节点可用。旧插件仍可连接，但不能提供新增字段。联网验证应使用明确经过代理的 HTTP／HTTPS 请求，并检查出口，不能仅凭“运行中”判断。

## 构建与发布

主应用按[开发与测试](DEVELOPMENT.md)构建，无需安装 Go。插件模块为 `:kernel-plugin`，工具链版本固定在 `native-kernel/go.version`；`:kernel-plugin:prepareProxyKernel` 自编译 Xray，并按 `native-kernel/artifacts.lock.json` 校验产物。

```sh
./gradlew :kernel-plugin:assembleDebug
```

插件默认构建 ARM64，实验性 x86_64 通过兼容性构建属性启用。插件发布工作流为 `.github/workflows/release-kernel-plugin.yml`，校验所关联主应用的版本、签名和发布材料。插件与主应用可独立构建，但签名及接口必须兼容。

Xray 及传递依赖的准确来源、版本、许可证与分发材料见 [THIRD_PARTY.md](../THIRD_PARTY.md) 和 [native-kernel](../native-kernel/)。发布验证应分别记录本地内核就绪、真实代理转发、安装／更新及受影响厂商设备的结果；未执行项目不得记为通过。
