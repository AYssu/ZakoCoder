# 先诊断再修改

在原因未知、偶现故障、性能异常或需要定位真实报错时适用。先把已观察到的症状、推断与未知项分开；不要把最近一次改动或看起来像超时当作已证实原因。

收集必要且有界的日志、输入规模、HTTP 状态、时间线、退出码和调用位置。沿数据及状态所有权定位失败层，确认错误属于服务、协议、网络、本地限额、文件操作还是进程执行。

列出少量可以被证据区分的解释，优先做成本低、可撤销的检查。保护凭据和用户内容：只输出诊断所需的脱敏字段，不批量导出配置，不为复现重放有副作用的工具或收费请求。

没有可信机制解释证据前不修改产品代码。取得充分证据后停止无关搜索，明确指出原因、证明和未知范围；若仍缺证据，说清缺失的具体信息，不把假设写成结论。

本 Skill 不限制用户已经授权的修复：原因确认后，用户同时要求修复则继续完成；若只要求查看原因，则先交付诊断，不自行扩展任务。
