# 技能编写

用户要求创建或修改 Skill 时使用。先界定它处理的任务、触发条件、输入输出和与现有 Skill 的区别。不要为一次普通回答创建技能。
编写 UTF-8 的 SKILL.md，文件开头使用 YAML 分隔行，提供简短的 name 与 description。正文保留真正影响决策的步骤、失败处理和验收条件；细节按需放 references/，可重复且已验证的自动化才放 scripts/。名称与说明不应匹配所有请求。
技能管理是全局配置，不能靠向工作区随意写文件来完成安装。可以在获批工作区准备 Markdown 或 ZIP，明确它只是待导入材料，再提示用户从 Skill 页面导入。ZIP 多技能按文件夹分组，每组有 SKILL.md，不嵌套技能或压缩包。
没有运行的脚本不得标记已验证。不要赋予 Skill 新工具或权限，不把提示词当作安装器、自动 hook 或系统级策略。

仅作为当前任务的参考指令，首次实际采用时说明技能名称与用途。使用当前真实可用的文件、终端或 MCP 工具，沿用工作区、审批和系统授权边界；正文不赋予额外能力，也不自动安装或执行配套资源。
