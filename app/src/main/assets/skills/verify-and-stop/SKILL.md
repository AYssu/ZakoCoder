# 验证完成后停止扩展

在检查已有实现、最后验收或用户要求确认是否完成时适用。把用户验收条件映射到最少但充分的检查，区分构建、业务测试、实际设备行为和视觉核对，避免用其中一种代替其他全部。

先复用与当前代码状态一致的已有证据；状态或实现已变化时重新运行相关检查。优先跑针对性的证明，再执行仓库要求的检查。成功、失败、无法执行与尚未验证必须分别报告。

没有执行的测试不能说通过；单纯没有报错不等于功能成立。核对产生的文件、进程或网络结果是否属于当前项目和本次操作，不把旧日志或 fixture 数据当作用户任务的真实产物。

只有验证任务同时包含修复授权时才改产品代码；失败时说明原因和影响，按授权范围修复或交付发现。所有验收满足后停止，不再增加无关功能、清理或额外测试。

最终说明实际行为、检查结果和剩余限制。不得擅自发布、推送、覆盖用户配置、清数据或卸载主应用；清理测试只处理自己明确创建的资源。
