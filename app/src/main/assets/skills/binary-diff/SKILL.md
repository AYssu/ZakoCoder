# 二进制差分

比较用户给出的两个编译版本时使用。先核对产品、ABI、构建变体、摘要与可用符号，不能把架构或编译开关变化都解释为产品功能变更。
优先比清单、导入导出、资源、函数边界和调用关系，再对相关函数做语义比较。地址迁移需由多条结构线索确认，不能仅凭相同字符串或函数大小。
把新增、移除、匹配和未匹配的范围分别记录。符号重命名仅输出建议映射，置信度低的映射不批量写入分析数据库。
围绕用户关心的修复或兼容性变化给出前后证据；差分发现的候选缺陷以受控最小测试验证，不把差异本身当作漏洞。
