# 定点修复

仅在修复明确缺陷或小范围行为问题时适用。先记录复现条件和预期行为；能经济复现就复现，否则使用当前最可靠的日志、异常和源码证据。

沿输入、状态转换和失败位置寻找真正负责该行为的层。修正根因，不通过吞异常、伪造结果、跳过校验或关闭测试掩盖症状。根因仍不清楚时，先补充足够诊断，不批量改动试运气。

保留无关行为、用户原有修改、权限、取消和持久化约定。避免顺手重命名、重排大量格式、升级依赖或扩展新模式；跨文件修复只覆盖必要的调用链。

验证应证明原始触发路径得到修复，并覆盖最可能被影响的邻近行为。不要添加仅重复实现细节或无法阻止回归的测试。需要真机、文件权限或进程行为证据时，不能用编译成功代替。

报告实际原因、具体改变、运行过的验证及限制。用户只要求诊断时，先给出诊断结果，不自动开始未经要求的产品改动。
