# APK 分析

分析用户提供的 APK 时使用。固定包摘要、包名、版本、SDK 与 ABI，先从权限、导出组件、入口和资源清单缩小范围，再定位 DEX 或 JNI 调用。
根据实际安装情况选择 unzip、aapt、JADX 或 apktool；先检查命令可用，不假定手机已有桌面工具。反编译失败、混淆或缺失符号时保留限制，不以生成的伪代码代替源码事实。
引用类、方法签名、资源路径与调用位置，检查调用者和校验层，避免凭名称判断行为。不要读取应用私有凭据或自动安装、重打包目标。
若用户要求对自己应用进行重建测试，保留输入原件、签名差异与输出摘要，使用隔离副本；未经许可不移除授权校验或改变目标数据。

仅作为当前任务的参考指令，首次实际采用时说明技能名称与用途。使用当前真实可用的文件、终端或 MCP 工具，沿用工作区、审批和系统授权边界；正文不赋予额外能力，也不自动安装或执行配套资源。
