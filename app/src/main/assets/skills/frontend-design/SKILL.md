# 界面设计与实现

仅在创建、修改或评审界面时适用。先确定用户任务、页面信息层级、关键操作及现有视觉规范。用户提供的原型、截图和组件规则优先；先看懂现有页面，不把相似名称当作已理解设计。

实现前形成简短设计决定：页面区域与顺序、主要和次要操作、字号与字重、间距和色彩用途、空态/加载/成功/失败状态。沿用适合项目的组件与技术栈；Android 原生项目保持 Compose，不为完成 UI 任意引入网页或新框架。

用对齐、留白、文字层级和分组表达关系，不把所有内容放成相同卡片，不用装饰替代状态语义。颜色、描边、图标和动效要能解释其用途。危险操作应有清晰层级和必要确认；只有图标的按钮需有无障碍名称。

文案说明用户能理解的实际动作，按钮与结果命名一致。错误解释如何恢复，空态提供可行入口；不要在产品界面塞内部实现细节或假数据。文案进入项目字符串资源。

覆盖小屏、滚动、软键盘、系统边距、亮暗主题和字体放大，保留可触达的操作区域与可辨的对比。检查每个入口是否真实可用，而非只做静态画面。

用现有截图、设备或浏览器工具检查最终界面，能取得截图就按原型逐项对照。没有视觉检查工具时明确说明限制，不能声称经专家评审或完全一致。仅在验收需要时继续打磨，保留无关页面行为。
