# 完成范围明确的功能

仅在实现新行为、接入能力或补全产品流程时适用。根据用户目标与仓库现状写出可观察的完成条件，区分必须实现的路径与本轮没有要求的能力。先读取入口、状态所有者、已有接口和相关设计规范。

沿用户实际操作把入口、数据、业务、持久化和错误处理接成可工作的闭环。优先复用项目已有边界，不为了少改文件把网络、进程或持久化塞进 UI；也不为了可扩展性提前建设后台、插件市场或多 Agent 框架。

每个新增状态、配置、依赖和服务都应能对应验收需要。处理真实的加载、空态、失败、取消及重新进入；不使用假日志、预置会话或虚构成功代替实现。

保护用户原有修改，遵守工作目录、运行环境和工具权限。涉及外部副作用仍走现有审批，不能把 Skill 当成额外授权。没有必要时不清理工作区、不升级依赖、不修改无关功能。

完成后运行与变更相关的验证，给出实际行为、结果和仍存限制。验收已满足时停止扩展，不把计划或 roadmap 中的后续工作标成已经完成。
