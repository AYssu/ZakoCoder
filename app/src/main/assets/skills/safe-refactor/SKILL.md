# 保持行为的重构

仅在用户要求整理结构、拆分职责、移动所有权或去除重复时适用。先说明本轮需要保持的可观察行为：接口、数据格式、默认值、错误、权限、取消、顺序及兼容性。

改结构前建立能覆盖这些行为的现有验证基线。识别代码实际所有者与调用关系，再逐步移动一个边界，保证每一步仍可编译、运行和审查。

不把未要求的功能改变、依赖升级、配置扩张和视觉改版混入重构。不能为了抽象而增加无使用者的接口，也不能用共享全局状态代替明确生命周期。

保存用户修改和原有异常传播方式；文件、URI、进程和网络仍由合适的层与调度器负责。不要通过放宽断言或删测试宣称行为保持。

使用相同证据比较前后结果，重点检查失败和取消路径。达到要求的结构且行为一致后停止，说明验证范围与不能证明的部分。
